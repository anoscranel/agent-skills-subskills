# Product discovery and framing

## Standard

Discovery begins with the opportunity, not the solution. The discipline is to fall in love with the problem: name the unmet need, the user who has it, and the outcome they want, before anyone sketches a feature. A framing that starts from a solution ("we should build X") inverts the order and spends the rest of the project defending the answer rather than testing the question.

Jobs-to-be-done is the sharpest framing tool: customers "hire" a product to make progress in a circumstance, so the unit of analysis is the job, not the demographic. The discovery question is what progress the user is trying to make, in what situation, and what they use now. The problem statement that survives is specific about user, circumstance, and desired outcome, and it names the current alternative the product must beat.

Primary sources: <https://www.svpg.com/> and <https://hbr.org/2016/09/know-your-customers-jobs-to-be-done>.

## Decision rules

- Start from the opportunity and the user outcome, never from a proposed solution.
- Frame with jobs-to-be-done: the progress sought, in a circumstance, against a current alternative.
- Name the target user and the situation specifically; "everyone" is not a target.
- State the desired outcome as a measurable change for the user, not a product feature.
- Identify the current alternative, including doing nothing, that the product must beat.
- Reject a framing whose only support is that a senior person wants it.

## Procedure

1. Write the candidate opportunity in one sentence: user, job, circumstance, outcome.
2. Name the current alternative and why it is inadequate.
3. State the desired outcome as a user-visible, measurable change.
4. List the assumptions the framing depends on, most fragile first.
5. Check the framing against real users before committing to a solution.
6. Record the framing and its assumptions for the discovery evidence to test.

## Anti-patterns

- Starting from a solution and retrofitting a problem to justify it.
- A target user defined only by demographics, with no circumstance.
- An outcome stated as a feature ("build a dashboard") rather than a user change.
- Ignoring the do-nothing alternative, so any improvement looks compelling.
- A framing backed only by the highest-paid person's opinion.

## Done checklist

- [ ] Opportunity framed as user, job, circumstance, outcome.
- [ ] Current alternative, including doing nothing, named.
- [ ] Outcome measurable and user-visible.
- [ ] Target user and situation specific.
- [ ] Assumptions listed, most fragile first.
- [ ] Framing checked against real users before solutioning.
