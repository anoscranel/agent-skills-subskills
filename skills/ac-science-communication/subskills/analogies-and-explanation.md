# Analogies and explanation

## Standard

The main barrier to explaining science is the curse of knowledge: the explainer cannot easily imagine what it is like not to know. Terms that feel obvious to a specialist are opaque to a lay reader. The craft is to build understanding from what the audience already knows, using concrete language, well-chosen analogies and visuals, and to check the explanation actually lands.

An analogy maps an unfamiliar concept onto a familiar one — but every analogy has limits, and a misleading analogy is worse than none. The discipline is to choose an analogy whose structure matches the concept's key feature and to flag where it breaks down. Visuals carry load that text cannot: a good diagram shows relationships, scale or process at a glance. Jargon is either removed or defined once in plain terms and then used consistently. The test is whether a lay reader can explain the concept back correctly, including where the analogy stops holding.

Primary sources: <https://www.aldacenter.org/> and <https://en.wikipedia.org/wiki/Science_communication>.

## Decision rules

- Start from what the audience already knows, not from the concept.
- Choose analogies whose structure matches the key feature.
- Flag where each analogy breaks down.
- Use visuals for relationships, scale and process.
- Define necessary jargon once in plain terms, then use it consistently.
- Verify a lay reader can explain the concept back correctly.

## Procedure

1. Identify the concept's key feature to convey.
2. Find a familiar analogue with matching structure.
3. State the analogy and where it stops holding.
4. Replace or define jargon in plain terms.
5. Add a visual for relationships or scale.
6. Test the explanation on someone from the audience.

## Anti-patterns

- Explaining in the terms the specialist uses by default.
- An analogy that misleads about the core mechanism.
- Jargon defined with more jargon.
- A visual that decorates rather than clarifies.
- Assuming the explanation worked without checking.

## Done checklist

- [ ] Key feature identified.
- [ ] Analogy structure matches the concept.
- [ ] Analogy limits flagged.
- [ ] Jargon removed or plainly defined.
- [ ] Visual clarifies relationships or scale.
- [ ] Explanation tested on a lay reader.

Layering is the companion technique to the analogy. Give the simple, slightly incomplete version first, then add the refinement once the basic model holds, rather than leading with the full complexity. Each layer should be true as far as it goes, so the reader is never asked to unlearn something later. A concrete example before the abstract principle lets the reader attach the concept to something specific. The order is familiarity, then concept, then precision — the reverse of the order a specialist would choose.
